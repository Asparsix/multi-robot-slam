\begin{abstract}
This document describes the multi-robot house mission system implemented in
\texttt{multi-robot-slam}: what problem is solved, how the stack is layered
(simulation, mapping, localization, CBBA task allocation, MAPF, and Nav2
execution), and how each concern maps onto concrete files in the codebase.
\end{abstract}

%=============================================================================
\section{Problem statement}
%=============================================================================

We want \textbf{four TurtleBot3 robots} in one simulated house to:

\begin{enumerate}[leftmargin=*]
  \item \textbf{Map} the environment collaboratively (or reuse a saved map).
  \item \textbf{Localize} each robot on that map.
  \item \textbf{Assign} a pool of reach-point tasks to robots
        (multi-robot task allocation).
  \item \textbf{Plan} motion so robots do not collide in space--time
        (multi-agent path finding).
  \item \textbf{Execute} those paths so robots actually arrive at every
        assigned task.
\end{enumerate}

Classical single-robot Nav2 only solves localization and (partial) execution
for one agent. It does \textbf{not} assign tasks across a fleet or guarantee
non-conflicting multi-robot plans. This stack adds \textbf{CBBA} (who does
which tasks) and \textbf{MAPF} (how they move without fighting), then uses
\textbf{Nav2} as the low-level driver.

each bundle leg $\rightarrow$ all robots finish every assigned task
(including leftovers so all \textbf{10} house tasks complete).

\midrule
\endfirsthead
\toprule
\textbf{File} & \textbf{Role} \\
\midrule
\endhead
\texttt{eticbba/cbba\_solver.py}
  & Core CBBA algorithm (bundles, consensus) \\
\texttt{eticbba/nav2\_path\_cost.py}
  & Cost oracle: Nav2 \texttt{ComputePathToPose} length; Euclidean fallback \\
\texttt{eticbba/cbba\_assign\_node.py}
  & ROS node: load tasks, run CBBA, write YAML \\
\texttt{eticbba/tasks/house\_10\_tasks.yaml}
  & 10 reach tasks + robot spawns + $K$ \\
\texttt{eticbba/launch/cbba\_house\_assign.launch.py}
  & Assign-only launch \\
\bottomrule
\end{longtable}

\textbf{What CBBA solves:} given robots and tasks, produce ordered
\textbf{bundles} per robot that maximize score (prefer more tasks / shorter
travel).

\textbf{Important:} CBBA is \emph{assignment}. It does \textbf{not} move robots.
But \textbf{scoring} calls Nav2 path length many times, which can time out under
4$\times$ Nav2 load. Euclidean fallback keeps assignment alive.

\textbf{$K$ and 10 tasks:} With $K{=}2$ and 4 robots, at most 8 tasks fit in
bundles. Leftovers (e.g.\ T03, T04) are attached in the mission coordinator so
all 10 can still be executed.

\subsection{Multi-agent path finding --- MAPF (L4)}

\begin{center}
\texttt{src/dual\_robot\_known\_map/scripts/prioritized\_mapf.py}
\end{center}

\textbf{Algorithm (short):}
\begin{enumerate}[leftmargin=*]
  \item Robots planned in fixed priority:
        \texttt{robot1 $>$ robot2 $>$ robot3 $>$ robot4}.
  \item Higher-priority path is reserved in $(x,y,t)$ and on edges.
  \item Lower-priority robot A*s around those reservations (can wait).
  \item Output path keeps wait cells (one pose per timestep) for space--time sync.
\end{enumerate}

\textbf{I/O:}
\begin{itemize}[leftmargin=*]
  \item In: \texttt{/swarm/robotN/goal}, \texttt{/robot1/map}, \texttt{/robotN/tf}
  \item Out: \texttt{/swarm/robotN/path}, \texttt{/swarm/paths\_ready}
\end{itemize}

This is \textbf{prioritized MAPF}, not optimal CBS/ECBS.

\subsection{Execution --- timestep Nav2 (L5)}

\begin{center}
\texttt{src/dual\_robot\_known\_map/scripts/mrpa\_executor.py}
\end{center}

\textbf{Why not one \texttt{NavigateThroughPoses}?} Dumping the whole MAPF path
into Nav2 lets robots free-run and break space--time sync. Instead:

\begin{lstlisting}[caption={Timestep execution loop.},label={lst:timestep}]
for t in 0 .. makespan-1:
    send NavigateToPose(pose[t]) to each robot
    wait until all are near (or wall-clock step timeout)
    advance
\end{lstlisting}

Publishes \texttt{/swarm/makespan\_complete} when a plan finishes.

\begin{lstlisting}[caption={Mission leg loop.},label={lst:mission}]
CBBA(bundles)
attach any unassigned leftovers to nearest/shortest robots
for leg = 0 .. max_bundle_length-1:
    publish /swarm/*/goal for this leg (idle robots hold pose)
    wait paths_ready
    wait makespan_complete or TF near goals
    mark COMPLETED task ids
assert all 10 tasks done  -->  ALL_TEN_TASKS_OK
\end{lstlisting}

\section{Design decisions and trade-offs}
%=============================================================================

\begin{table}[htbp]
\centering
\caption{Key design decisions.}
\label{tab:decisions}
\begin{tabular}{@{}p{3.2cm}p{4.5cm}p{4.5cm}@{}}
\toprule
\textbf{Decision} & \textbf{Why} & \textbf{Trade-off} \\
\midrule
Namespaced TF per robot
  & Matches Nav2 multi-robot practice
  & Swarm nodes must subscribe per-robot TF \\
AMCL owns \texttt{map$\rightarrow$odom}
  & Single localization source
  & Needs good initial pose / scan sync \\
Prioritized MAPF
  & Simple, fast, good enough for demo
  & Not optimal; priority bias \\
Timestep \texttt{NavigateToPose}
  & Preserves MAPF time sync
  & Slower; many Nav2 goals \\
Nav2 as CBBA cost
  & Path length reflects map obstacles
  & Planner load $\rightarrow$ timeouts; Euclidean fallback \\
$K{=}2$ + leftover attach
  & Stable CBBA under load; covers all 10
  & Leftovers are greedy, not re-auctioned \\
\bottomrule
\end{tabular}
\end{table}

\section{Known limitations}
%=============================================================================

\begin{enumerate}[leftmargin=*]
  \item Four Nav2 stacks on one PC stress DDS/CPU (TF blips, planner timeouts,
        step timeouts).
  \item CBBA $\neq$ motion --- timeouts during CBBA are usually cost-query
        overload, not driving failure.
  \item Prioritized MAPF is suboptimal vs CBS/ECBS.
  \item Step timeouts in the executor advance anyway; sync is soft under load.
  \item Optional future: replace Nav2 execution with a thin tracker (Option~B)
        to cut load.
\end{enumerate}
